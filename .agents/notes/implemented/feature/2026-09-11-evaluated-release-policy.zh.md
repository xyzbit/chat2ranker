# Agent Note: 评测发布门槛

Status: implemented

[English](2026-09-11-evaluated-release-policy.md) | 中文

## 问题

完成评测不能证明发布质量。如果没有固定数据集并检查实际结果，调用者就可以将低质量或无关的 Run 标为通过。证据还可能在审阅与发布之间过期；被拒绝的尝试需要持久解释，但不能产生成功发布历史。

## 决策

Agent 详情只保留一个「去发布」入口。操作者 API 在租户内根据不可变发布历史查找部署，并选择最新匹配项，避免后续别名移动让已发布版本误入无关的创建流程。没有匹配时打开预填创建表单，再进入所选版本的发布确认。独立的部署导航打开列表，不隐式选择详情。

Agent 资产关联可选的默认开发集和回归集 Dataset 资产。Dataset 保持通用，每次发布冻结实际使用的 DatasetVersion。Deployment 保存数值发布规则，与不可变执行限制分开。持久任务冻结同口径开发评测证据，默认先运行回归，再在事务中发布。发布时再次检查别名和策略版本。失败保留别名并记录拒绝决策；显式覆盖必须填写原因，并保留失败检查。确认前主动跳过回归会记录独立的结果。[发布流程](../../../../rank/docs/release-policy.md)定义 API 和指标语义。

## 考虑过的替代方案

**接受任何已完成 Run。** 拒绝，因为完成状态不能证明达到质量门槛，也不能阻止无关数据集为版本提供通过依据。

**要求每个 Trial 都有效。** 不将其作为无条件规则，因为可配置的覆盖率门槛必须有实际意义。需要更严格的策略时可设置 100%；零有效 Trial 始终阻止评测发布。

**信任预检，或将拒绝记录写入会回滚的事务。** 拒绝，因为证据可能在审阅后过期，策略和别名可能变化，而回滚会抹去拒绝记录。

## 影响

一个端点表示一个稳定访问目标和一个当前版本，不同端点区分环境。创建后保持未发布，新建 Agent 版本不能绕过发布审阅。已有别名记录作为历史详情保留。API 路径与持久化 Deployment 标识符保留原名。普通发布无需选择路由，同时保留显式 API 引用。

接入将密钥选择或就地创建与可执行示例放在一起。时间戳名称和当前已有端点及操作的全选权限减少重复配置；提交的访问列表固定，不扩展到未来端点。只保存哈希无法恢复明文，因此已有 Key 需要填写保存的原值。只有明确复制命令时才包含密钥；编程 Agent 指令和浏览器存储不接收密钥。追加指令与调用方函数属于端点标准能力，保留校验和调用方执行。本地文档中心管理产品示例，免密验收执行共用的示例生成器。

默认值减少重复选择，不限制数据集复用。新草稿解析最新数据集版本；已有任务保持冻结的版本和规则。任务/Run 创建、取消和最终别名切换各自保持事务一致性。对话确认引用将进度恢复到原事件位置。审计快照在后续编辑后保留历史门槛。回滚追加发布记录，并保持已有会话的版本绑定。免密的 worker/Responses 组装快照及桌面/手机浏览器流程覆盖发布和刷新；定向服务测试覆盖精度、重启、取消、幂等和冲突。操作者认证、流量权重和自动回滚不属于此决策。
