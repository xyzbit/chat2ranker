# Agent Note: Rank 流式控制与上下文详情

Status: implemented

[English](2026-08-24-rank-streaming-control-and-inspector.md) | 中文

## 问题

Rank 的控制对话要等待 DeepSeek Harness 完成整轮后，才显示用户消息和执行结果。测试集与 Agent 引用只是普通文本，测试集用例和运行详情则在聊天中展开。控制工具也没有不可变追加操作，因此用自然语言新增用例会创建无关的测试集资产。

## 决策

Rank UI 立即插入用户消息，并启动一个异步 Control Turn。Control Host 把持久 DSH Session Event 投影成一组精简 SSE 事件：Turn 生命周期、安全的思考状态、工具生命周期和助手文本增量。浏览器永远不会收到原始推理文本。完成后的 DSH transcript 仍是持久对话，并继续同步到 Rank。

输入框 Mention 将测试集或 Agent 版本 ID 与可见文本分开传输。Control Host 把引用加入模型可见用户消息，并在生成用户 transcript 时移除引用块。输入框通过 Mention 完成无歧义的对话式选择，并只保留三个紧凑快捷操作：运行配置、实验表现和导入用例。

聊天只保留紧凑的运行摘要。实验工作区默认关闭；桌面端打开后停靠在聊天右侧，窄屏则覆盖聊天。配置页签展示已选测试集和 Agent 版本，运行记录页签只展示当前实验的 Run。测试集、Agent、Run 和用例操作会打开工作区并定位所属实体；宽屏开关为用例列表、日志、Trial 与产物提供更多空间，而不增加第二条产品路由。新实验和实验记录仍是全局顶部操作，不属于工作区导航。

运行准备和实验表现是持久 A2UI 对话事件，不再是聊天尾部的永久卡片。`rank_prepare_run` 只在出现运行意图时生成确认快照；`rank_show_experiment_results` 读取当前实验的全部 Run 和被测 Agent 版本，只在出现实验数据、结果、表现或对比意图时生成整体图表。输入框快捷按钮发送相同意图。运行记录页签是专门的检查页面，因此可以持续显示整体图表。图中每个点代表一个 Run，纵轴是通过率，横轴可在已知成本与总时延之间切换；没有完整成本时默认选择时延。缺少所选指标的 Run 仍计入总数但不绘制；选择点会在实验工作区打开对应的不可变 Run。

Agent Tool 和 Skill 引用使用可搜索多选框，选项来自已有 Agent 版本和少量种子目录，同时保留明确输入自定义 ID 的路径。表单说明每个 Tool 必须由所选 Runner Adapter 提供，每个 Skill 必须安装在执行环境。直接提交会创建不可变 Agent 版本；对话入口会把同一配置投影为 `rank_create_agent` 或 `rank_create_agent_version`，后者从基础版本复制未提供的字段。

实验工作区在测试集详情中提供用例级新增与编辑操作，在 Agent 详情中提供编辑操作。这些表单不会原地更新已选资产：保存会在同一资产族中创建下一个版本，并立即为实验选中它；历史 Run 仍保留冻结的版本 ID。

准备卡和运行确认卡中的测试集、Agent 区域仍以查看详情为主体操作，同时增加一个紧凑切换图标，用于打开对应资产选择器。Run 成本继续严格区分完整性：只要任一 Trial 成本未知，就把已知聚合值向下取整并显示为 `≥$0.0599` 这样的下限，同时标记为“已知成本”；成本对比图用空心虚线点展示这些下限，不再隐藏对应 Run。实验列表中的 Run 摘要与完整 Run 一样携带 `costKnown` 事实。

控制 Agent 的最终回复使用 Rank Message JSONL，并只包含摘要、正文、列表、事实、提示和代码这组精简 Block。浏览器在模型输出进入 UI 时验证数据，并通过产品自有排版渲染；流式传输中尚未完成的一行在构成完整对象前不会显示。已有 Markdown 消息使用安全的旧格式渲染器，不再直接暴露语法标记。复制任一格式都会输出 Markdown：先使用异步 Clipboard API，失败后再尝试同步浏览器降级方案；按钮会在点击位置明确显示成功或失败。持久 DSH transcript 与 Rank 消息内容仍保留模型原始输出。

`rank_add_dataset_cases` 必须接收基础测试集版本和新增用例。Rank 在同一个 Repository 事务内复制基础用例、创建下一个不可变版本，并为实验选中该版本。基础版本不会被更新。

## 曾考虑的替代方案

**前端伪造进度。** 不采用，因为定时文案可能与 Harness 实际状态不一致。当前投影来自真实 DSH 工具和消息事件。

**展示原始思维链。** 不采用，因为产品只需要可观察进度。通用思考状态和工具生命周期已经足够，也不会泄露模型隐藏推理。

**把全部详情放入聊天。** 不采用，因为用例列表、多次 Trial、日志和产物会淹没实验中的关键决策。

**使用模态详情检查器。** 不采用，因为模态层会遮住解释当前版本或 Run 的对话。停靠工作区保留这些上下文，同时仍按需出现。

**使用逗号分隔的自由输入能力字段。** 不采用，因为能力 ID 难以发现且容易输错。可搜索多选展示已知选项，同时保留显式的自定义 ID 路径。

**修改已选测试集。** 不采用，因为运行会冻结版本 ID，并且必须可复现。追加操作始终创建新版本。

**所有手动修改都通过对话完成。** 不采用，因为在实体详情中修正一个用例或 Agent 字段更快、更明确。对话仍用于意图驱动和批量修改。

**把部分聚合成本隐藏为未提供。** 不采用，因为这会丢弃已经持久化的有效计费信息。把已知金额表达为下限，同时保留了可用性与真实性。

**直接渲染模型 Markdown。** 不作为主格式，因为模型自行选择标题、表格和列表会让消息密度不可预测。Markdown 只保留为旧数据导入和复制格式，不再承担视觉协议。

## 后果

消息发送会立即反馈，控制过程可见，`@` 引用能够解析到稳定版本。内存中的 Control Turn SSE 会为迟到订阅者保留五分钟，但不能跨 Control Host 重启；持久 DSH transcript 仍可恢复已完成的对话。实验工作区负责读取大量详情和手动选择资产，聊天仍是主流程。工作区打开时会与桌面聊天共享宽度；窄屏则有意让工作区占满视口。图表无需新增仪表盘路由即可比较完成的 Run。新增用例或修改 Agent 能力会增加一个不可变版本，而不会改变历史运行。
