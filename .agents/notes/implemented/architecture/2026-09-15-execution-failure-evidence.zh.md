# Agent Note: 在产物失败时保留已观察到的结果

Status: implemented

[English](2026-09-15-execution-failure-evidence.md) | 中文

## 问题

所有产物进入持久存储之前，模型可能已经完成并产生已知用量。如果只在全部上传成功后保存结果，后续传输失败就会丢掉回复、用量和已发布引用。为了重新生成文件而重放调用，可能重复执行外部操作。

## 决策

两种 Executor 都通过成功结果使用的证据发布路径保留有效的 Worker 失败响应。发布前必须核对协议版本、执行身份与终态。远程命令流区分正常退出的 Worker（退出码 1 且响应为匹配的失败）与传输中断、输出损坏、异常终止或矛盾的成功响应。已知失败仍保留失败状态、原始错误、输出、用量及可读取产物；产物发布错误追加到 Worker 错误中，不替换原始错误。两种结果均不触发自动重放。

本地与 OpenSandbox Executor 在发布产物前持久化已脱敏的观察结果，其中不含尚未确认的产物引用。每个文件成功上传后，加入其内容寻址引用，并在处理下一个文件前保存累计证据。SQLite 使用已有的结果列，PostgreSQL 使用已有 JSON 结果字段，无须迁移存储格式。

`Repository.RecordEvidence` 仅接受 running 或 cancelling 状态下匹配的非零尝试代次。终态记录拒绝迟到证据。它只更新已观察结果，不改变生命周期状态、不确认 River job、不释放运行时容量。失败、取消及拥有者丢失转换保留已提交的证据。正常完成仍须等必要产物与运行时清理确认后，原子发布完整结果、终态事件和 River 完成状态。

因此，Execution 在运行、失败或取消时也可能有 `result`。字段存在不代表调用成功，消费者必须依据 `status`。产物读取仅授权记录中的引用，失败执行中的引用也可读取。即使没有任何产物上传成功，记录也保留已知输出和用量。文件在远端提交成功、但数据库写入失败而未记录引用时，仍属于无引用对象，由现有运维保留策略处理。未上传文件不会被声明为可读取。

证据持久化或产物传输失败时，适配器停止并尝试有时限的清理，不会为了恢复产物而重新执行模型或工具。数据库失联可能让已观察结果无法持久化；未提交权威终态时，恢复流程明确报告结果未知。内存输出不构成恢复保证，本决策也不会无限保留 Sandbox 供后续人工提取。

产物预览通过 JSON 保留原始字节：有效文本的 `encoding` 为 `utf-8`，其他内容为 `base64`。`truncated` 表示编码前的一 MiB 字节前缀。校验摘要前需解码 base64；截断预览不能用于完整文件校验或下载。Rank 转发编码信息，界面仅对完整响应提供二进制下载。

## 考虑过的替代方案

**仅在终态成功时发布全部引用。** 成功路径更短，但后续失败时会丢掉已知用量和成功上传的证据。

**缺少必要产物仍返回成功。** 掩盖执行不完整，违反完成前必须持久化引用证据的要求。

**存储恢复后重跑 Harness。** 可能重复付费模型调用和外部工具操作，队列重试不授权这种重放。

## 影响

SQLite 和真实 PostgreSQL 测试覆盖证据保留、取消、不匹配代次和终态写入拒绝。本地发布测试中断第二次上传，检查只有首个文件被授权。[依赖验证器](../../../../rank/deploy/k8s/verify-dependencies.py)运行真实 DSH 工具，在观察到外部操作后移除 PostgreSQL，并在真实 TCP 流中中断指定 S3 请求体。其快照要求只有一次执行尝试、一次外部操作、已确认清理，并且仅在模型完成后上传失败的场景保留已知证据。已有产物和恢复后的新调用必须仍可读取。

[打包生命周期案例](../../../../rank/examples/execution-lifecycle/README.md)故意让确定性 Harness 输出不符合请求的 schema。本地和远程路径在 SQLite、PostgreSQL/River 下均要求失败状态、保留输出/用量/结果产物、重复提交只有一次尝试及已确认清理。命令流测试要求即使已收到进程退出帧，截断的传输仍不能视为正常退出。

每个产物增加一次累计结果的数据库写入，数量和大小仍受 Executor 配置限制。这是当前尝试的证据快照，不是通用检查点引擎，也不承诺恢复未提交内存。剩余生产要求由[方案](../../proposed/architecture/2026-09-14-rank-production-execution.md)维护。
