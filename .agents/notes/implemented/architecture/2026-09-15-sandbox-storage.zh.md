# Agent Note: Rank Sandbox 实验中的有界可写存储

Status: implemented

[English](2026-09-15-sandbox-storage.md) | 中文

## 问题

产物导出上限不能约束运行中的 Harness 创建大量文件、写入工作区之外或填满容器层。OpenSandbox 向停止的容器注入运行时；根文件系统只读时，Docker 拒绝该注入。

## 决策

专用 Docker 生命周期服务具有经过配置校验的 Rank 只读运行时模式。它通过 Docker API 将镜像文件系统设为只读，配置有界 tmpfs 区域和共享内存，禁止超出必需内存上限的 swap，并轮转容器本地日志。可写存储是临时的，共享容器内存预算。字节上限和 inode 额度属于部署配置，不是用户选择的产物上限，也不扩展公共 Execution API。

DSH 适配器为提示词与历史启动传入 Node 的 `--expose-internals` 参数。即使在 headless profile 中，打包 CLI 的配置监视服务也需要它；适配器不能依赖宿主机 Shell 提供 Node 选项。

Rank 镜像在构建时包含固定版本的 execd 二进制与受保护的 PID 1 启动器。此模式跳过运行时注入，拒绝请求卷、扩展、网络策略 sidecar、服务配置挂载和镜像声明的卷。这些拒绝防止引入额外可写挂载或无界隔离覆盖层。未实现打包 Rank 启动流程的镜像会启动失败，不回退到本地执行或可写根目录。检查版本的 OpenSandbox 构建补丁在源代码偏移时失败。

此模式限制完整容器内的普通可写文件存储，包括不经过 DSH 工具策略的 UID 1000 原生命令。只读镜像路径不能写入；输入、工作区和产物共享同一个额度。临时文件与共享内存分别限额。日志轮转按阈值限制保留文件，不是包含 Docker 元数据的精确宿主机磁盘字节上限。内存耗尽可能先于 tmpfs 字节上限终止任务；已有失败/未知结果与清理规则继续适用。

## 考虑过的替代方案

**只限制产物导出或单个文件。** 两者都无法约束运行时写入总量、inode 耗尽或其他可写目录。

**可写根目录加工作区 tmpfs。** 容器层和镜像声明的卷允许写入该挂载之外。只读根目录加额外卷拒绝让允许写入的区域明确可查。

**增加文件系统配额管理或第二套 Sandbox API。** 实验需要能容纳于分配内存预算的短期工作区。Docker 原生 tmpfs 限制满足该范围，无需特定宿主机文件系统配置；持久或更大的工作区需要单独设计存储。

## 后果

[实验教程](../../../../rank/deploy/k8s/README.md#bounded-writable-storage)维护配置和命令。通过鉴权 API 运行的原生进程实验及仓库快照要求总字节/inode 耗尽、根目录写入拒绝、其他挂载拒绝，以及清理后写入成功。[报告](../../../../rank/deploy/reports/2026-09-15-sandbox-storage.md)记录镜像身份和平台回归证据。由于镜像提供自身启动器，受保护寿命验证仍为必需项。

这是专用 Docker 实验中强制执行的配置，不保证任意 OpenSandbox 部署、持久卷、恶意内核漏洞或生产出口控制。[出口实现](2026-09-15-sandbox-egress.md)单独控制传输目标。生产身份、主机容量和长寿命工作区存储仍是[生产提案](../../proposed/architecture/2026-09-14-rank-production-execution.md)中的独立要求。
