# Agent Note: 冻结 Sandbox 出口规则与受保护的网络初始化

Status: implemented

[English](2026-09-15-sandbox-egress.md) | 中文

## 问题

Docker 私网端点和只读文件系统不能约束外连。Harness 可以绕过配置的 HTTP 代理和 DSH 工具直接打开套接字。网络限制还必须在生命周期服务失联后继续有效，并与已接受任务保持一致。

## 决策

Execution 在入队前将规范化的传输层允许列表冻结到 `RuntimePlan.egress`。运维通过 `-sandbox-egress-policy` 或 `EXECUTION_SANDBOX_EGRESS_POLICY` 配置 IPv4/IPv6 CIDR、TCP/UDP 和目标端口。空策略禁止新的外部连接；端口零允许所选协议的全部端口。未知 JSON 字段、无效地址前缀/协议和端口溢出会拒绝配置；规则使用独立副本并排序、去重。配置不同的 Worker 不能领取已排队请求，重复提交保留原策略和尝试代次。

专用 Docker 配置在独立网络命名空间中调用打包的 `network-init` 入口，仅在受保护的启动阶段授予 NET_ADMIN。在暴露 execd 前，PID 1 使用固定版本的 iptables 工具安装 IPv4 和 IPv6 过滤表，默认拒绝 OUTPUT 与 FORWARD。允许本地回环以及已建立/关联连接的回复。规则安装失败或缺少策略会停止容器，不回退到仅代理限制或本地执行。

PID 1 随后通过 `setpriv` 替换自身，从能力边界集合移除 NET_ADMIN 和 NET_RAW，并清除可继承/ambient 能力。重新执行替换全部 Go 运行时线程。PID 1、root 命令守护进程和后代不能重新获得这些能力，原有绝对寿命仍然生效。生命周期服务失联后，内核规则继续存在；不存在独立防火墙 sidecar 在任务存活期间清除规则的情况。

此策略约束目标 IP 前缀和传输端口，不约束域名、HTTP 路径或发送给已允许服务的内容。DNS 不会被隐式放行。使用主机名时，运维必须明确允许解析器与目标地址；DNS 结果变化需要审核并更新策略，或采用单独管理的出口网关。策略变更属于空闲维护操作：已接受任务保留原策略，规则不匹配的 Worker 让其继续等待，不扩大访问权限。入站服务授权与出站控制分别处理。

## 考虑过的替代方案

**只配置代理环境变量。** 原生套接字可以忽略这些变量。限制必须由包含完整运行时的网络命名空间执行。

**立即接入 OpenSandbox 出口 sidecar。** 其持续维护的 DNS/nftables 实现仍适合动态域名策略，但固定版本的 Docker 集成需要处理宿主机端口、共享可写卷和独立 sidecar 清理。初期固定目标策略使用内核过滤器与既有受保护运行时生命周期，不重写域名过滤和凭据拦截。

**执行期间始终授予 NET_ADMIN。** 高权限命令守护进程或后代可能修改规则。该能力仅用于启动，在接受命令前通过进程替换移除。

## 后果

[配置与实验](../../../../rank/deploy/k8s/README.md#runtime-egress)说明专用实验策略。[网络报告](../../../../rank/deploy/reports/2026-09-15-sandbox-network.md)区分真实 IPv4 TCP/UDP 测量与 IPv6 规则检查。必须有可达的对照目标、目标端请求记录、进程能力移除及生命周期服务失联证据，客户端超时本身不能证明限制生效。解析与队列测试拒绝无效策略和规则不同的 Worker，PostgreSQL 测试保留新增运行计划字段。

实验只允许专用 Docker 子网中的 TCP 8800，使临时的确定性模型/工具服务仍然可用。这是实验策略，不是生产租户策略。生产需要明确收窄目标、受限身份与主机容量验证。此传输策略不提供动态 DNS/域名授权、入站租户隔离或 TLS 内容检查。[生产提案](../../proposed/architecture/2026-09-14-rank-production-execution.md)保留这些部署差异。
