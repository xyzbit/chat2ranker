# Agent Note: 通过 OpenSandbox 远程执行

Status: implemented

[English](2026-09-15-execution-opensandbox.md) | 中文

## 问题

Worker 进程与本地子进程共享主机。拆分 River 消费者不能独立限制远程运行时的寿命，也不能在消费者消失后保留运行时身份。Sandbox 创建和命令执行也可能已经成功，但响应丢失。

## 决策

OpenSandbox Executor 在可丢弃容器中运行完整打包的 DSH 或确定性 Harness。Rank 保留 Execution API；Sandbox 生命周期由 Executor 内部管理。后端显式选择，绝不回退到本地执行。不兼容的消费者延后已冻结请求，不启动其运行时。

PostgreSQL schema 6 与 SQLite schema 10 持久化创建意图、服务地址、拥有范围、不可变镜像、绝对到期时间和远程句柄，与 Worker 拥有者分别记录。先保存创建意图，再发起一次创建请求；先保存句柄，再访问命令服务。创建与命令关闭 SDK 自动重试。终态清理核对器可按精确的范围、Execution 与尝试代次元数据找回丢失句柄，删除所属运行时并确认删除。创建结果不明且未发现资源时，仍保留未知状态，因为不能排除迟到创建。服务地址或范围变化不授权通过其他服务清理。确认只清除已有清理义务，不改变业务结果。

镜像中受保护的 root PID 1 使用受限环境启动 execd，并在持久化的截止时间退出。内核随后终止整个 PID 命名空间，包括已脱离的后代进程。Harness 命令使用 UID/GID 1000，不能获得 execd 令牌、Docker socket、数据库凭据或生命周期密钥。带鉴权的命令代理必须与生命周期服务同源，并拒绝重定向。每个运行时配置 CPU 与内存限制。服务端 TTL 的协议下限为 60 秒，PID 1 则独立执行更短的任务截止时间。

Linux 运行时闭包包含与入口包版本一致、按架构选择并验证归档完整性的 Landlock 程序，以及固定版本的 Bubblewrap。DSH 保留既有只读 Shell 策略和运行时能力探测。安装程序不等于内核支持该能力；找不到可用的隔离实现时拒绝工具执行，不会以无隔离模式运行。

私有输入上传使用 execd 以数字编码的权限值 `600`。产物导出以 Harness 用户运行，只在产物根目录内打开文件，不把 Harness 提供的路径交给高权限文件下载接口。传输校验数量、字节上限与最终摘要；内容寻址发布前会脱敏已知凭据，包括压缩的 DSH 日志。正常完成先发布产物再销毁运行时。上传或命令失败仍执行有时限的清理；无法确认停止时保留容量。[已观察证据](2026-09-15-execution-failure-evidence.md)在失败后保留已知输出、用量和已确认引用。

命令结束与传输保活相互独立：终态事件之后的 `ping` 被忽略。结束后的输出、第二个终态事件、格式错误的帧和截断的 HTTP 响应仍产生未知结果。只有保活事件不能证明命令已结束。

[资源池](2026-09-15-execution-runtime-pool.md)在排队前冻结分配目标与单容器限制，并在创建运行时前预留共享 CPU/内存预算。未知尝试通过同一个清理义务保留该预算。

专用 Docker 实验为打包镜像强制执行[有界可写存储配置](2026-09-15-sandbox-storage.md)。这属于部署配置，不保证任意 OpenSandbox 服务。

[出口实现](2026-09-15-sandbox-egress.md)将传输规则与分配计划一同冻结。专用 Docker 配置在暴露 execd 前调用受保护网络初始化，并通过 PID 1 替换移除网络管理能力。

幂等比较使用请求的持久化 JSON 表示。可选空集合与 JSON 数字在重复提交后不会产生虚假冲突；修改配置仍然冲突。

## 考虑过的替代方案

**暴露第二套公共 Sandbox API。** 没有已接受的环境复用需求，却增加了 Rank 调用方的生命周期选择。Execution 仍是调用方的工作单元。

**依赖服务端 TTL 或重试响应丢失的命令。** 服务失效后无法执行 TTL 清理，重复命令可能重复模型费用或工具副作用。独立的运行时截止时间与明确的未知结果保留了这些区别。

**通过高权限接口下载产物。** Harness 控制文件路径和符号链接。同一个低权限身份下的受限读取器可以避免这些路径读取守护进程私有文件。

## 后果

[Docker 实验](../../../../rank/deploy/k8s/README.md)将生命周期服务放在 Linux 内运行，使 macOS 上的代理能够访问 Docker 桥接地址。只有该服务获得 Docker socket，它属于可信基础设施。[远程案例](../../../../rank/examples/execution-lifecycle/README.md)在 SQLite 和 PostgreSQL/River 模式中对实际打包 API 结果建立快照。真实 DSH 集成使用确定性模型服务。故障测试覆盖创建响应丢失、延迟发现、句柄持久化失败、异源端点与过期尝试；独立寿命实验在脱离的任务运行期间强制停止生命周期服务。

可选 minikube 模式通过 Kubernetes Service/EndpointSlice 连接外部 Docker 服务。API/Worker Pod 使用远程适配器与 S3，Harness 容器在 Worker Pod 外运行。完整平台验证器检查远程分配身份、端点/聊天/试用行为、保留的 S3 证据，以及 Rank 替换和 Worker 缩到零之后的恢复。Pod 就绪后还需通过网关健康检查，再读取持久结果。切换后端属于空闲实验环境的维护操作；已经接受的排队工作保留原来的冻结后端。

[Worker 拥有者丢失实验](../../../../rank/deploy/reports/2026-09-15-owner-loss.md)先观察真实 Bash 工具操作与文件写入拒绝，再确认 Worker 进程因 SIGKILL 退出。未知结果、故障后取消和已提交结果重放符合组装应用快照。远程运行时删除后才清除清理预留，外部操作只有一次。这是在报告所列 Linux 内核及安全配置下使用确定性模型取得的证据。

此适配器不证明生产网络出口策略、磁盘硬配额、任意恶意代码隔离、sidecar 清理、工作区恢复或物理主机容量。服务部署不能注入主机挂载或未请求的 sidecar。创建结果不明且发现为空时，容量可能长期保留。[生产提案](../../proposed/architecture/2026-09-14-rank-production-execution.md)保留剩余隔离、部署与扩缩容验收工作；[实验报告](../../../../rank/deploy/reports/2026-09-15-opensandbox.md)记录已验证范围。
