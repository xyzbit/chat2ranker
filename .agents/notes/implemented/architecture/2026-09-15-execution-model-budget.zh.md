# Agent Note: 冻结 DSH 模型请求预算

Status: implemented

[English](2026-09-15-execution-model-budget.md) | 中文

## 问题

执行超时和单次错误的重试上限不能限制模型请求总数。工具循环、重复的暂时错误或辅助模型调用可能在一次执行中消耗很多请求。增加 Worker 副本不能重置已接受执行的预算。

## 决策

Execution 在准入时为支持该能力的适配器解析模型请求总上限。服务参数默认为 32，请求只能缩小它。解析值独立于幂等比较使用的不可变请求保存，因此修改服务默认值也不会改变重提请求的额度。SQLite 和 PostgreSQL 持久化预算，内部 Worker 协议 2 显式传递该值。具备该能力的新 Worker 在启动前拒绝缺少已解析预算的旧 DSH 任务；不具备能力的 Worker 将带预算任务留在队列。容量投影排除不兼容任务。

第一方 DSH 适配器在已有 `llm/stream` 扩展点挂载本次调用拥有的插件，在调用下一个监听器前同步预留。经过该 DSH LLM 服务的所有请求（包括重试、压缩和辅助调用）都消耗同一总额度。供应商适配器保留已有的有限重试策略，并禁用底层 SDK 重试；新增总额度也限制连续的失败与恢复循环。超出总额度的请求在派发给供应商前抛出插件错误，避免模型错误恢复逻辑再次启动它。独立的 Execution 与 Sandbox 截止时间继续限制等待和清理。

每个已接受的执行启动新的 DSH 进程。应用不重试已经启动的调用，因此进程内计数器不会在拥有者丢失后重建，也不会被队列投递重置。原始请求和错误仍保留在原生会话事件中，Execution 记录保留冻结预算。不增加模型可见文本或通用调度器。

后续模型调用耗尽预算时，DSH 适配器保留原生会话历史中已经观察到的用量。失败不代表零用量；缺失用量仍明确标记为不可用。

能力声明是显式的。原生 CLI 和自定义命令适配器不声明此限制；请求该预算时准入失败。配置的 DSH 镜像必须一并打包插件与 Worker 协议。这是协作式应用计量，不构成针对工具原始 socket、插件移除或任意代码的安全隔离，也不替代生产身份、供应商 RPM/TPM、输出 token 限制或费用预算。实现这些要求时，再单独决定共享模型网关。

## 考虑过的替代方案

**统计 River 投递次数。** 投递次数不是模型请求次数；一次 Harness 调用可以发起多个请求，重复投递已完成任务则不会发起任何请求。

**只缩短执行超时。** 请求突发可能在定时器到期前用完额度；慢供应商也可能只用少量请求就耗尽时间。

**重写供应商重试，或仅为该上限新增模型网关。** DSH 已有单次尝试适配器和有限重试策略。小型监听器限制本次调用总工作量，无须重复传输实现；它不宣称提供分布式供应商配额。

## 影响

[minikube 报告](../../../../rank/deploy/reports/2026-09-15-model-budget.md)记录供应商侧请求数、远程打包快照和最终镜像清理检查。实际远程流包含终态后的保活；Executor 忽略保活，但不接受不完整的命令结果。

[运行时参考](../../../../apps/execution-runtime/README.md)定义插件范围。构建后的 DSH 测试分别通过提示词和结构化历史驱动，统计持续 429、认证失败与暂时错误恢复时的真实本地 HTTP 请求数。[平台验证器](../../../../rank/deploy/k8s/verify-platform.mjs)将公开失败结果及供应商侧请求数与仓库快照比较，重提同一逻辑请求，并确认清理。Repository 测试验证存储与容量投影保留预算；应用测试拒绝不支持的适配器，并确认默认值变化不会改变已接受上限。

[生产方案](../../proposed/architecture/2026-09-14-rank-production-execution.md)仍要求共享供应商限制和真实供应商验证。本上限控制单次执行的请求放大，不证明这些独立要求已经完成。
