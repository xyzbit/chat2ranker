# Agent Note: 评测调用持久派发

Status: implemented

[English](2026-09-14-rank-evaluation-dispatch.md) | 中文

## 问题

恢复后的 Trial 可能重复执行远端已接受、但本地尚未提交结果的候选或裁判。用尝试次数生成提交键，会把传输恢复变成新的模型或工具调用。重启后读取当前裁判绑定，也会改变已经接受的评测配置。在核对调用之前把 Run 标记为取消，不能证明其运行时工作已经停止。

## 决策

[评测派发](../../../../rank/backend/internal/app/evaluation_dispatch.go)在 Run/Trial 准入事务中保存每个候选请求。只有缓存的候选结果和确定性检查允许时，才创建裁判请求。逻辑键包含 Run、Trial 和阶段/标准身份；传输尝试与进程重启不改变它。用户显式重新评测会创建新的 Run/Trial 身份。

Run 准入在取得业务事务锁之前检查运行时可用性并解析系统裁判绑定。事务核对所选版本，把裁判连接/模型、租户路由和执行超时与 Run 一起保存。服务请求、普通评测、对比与发布回归共享持久仓储，不在外部模型或 Execution 调用期间持有数据库事务。模型凭据留在 Execution；Rank 只保存引用与请求数据。

调用记录保存原始请求、可能已提交标记、Execution ID、事件游标及缓存的权威结果。投递和观察错误重试同一个请求。事件投影与游标推进在同一事务提交。派生阶段事件使用稳定键；Trial 完成和费用汇总保留已有事务结果身份。继续裁判工作时复用已经成功的候选。Rank 不自动重跑失败的候选或裁判；已知失败调用的用量和 Execution 引用仍保留在 Trial 结果中。结果未知仍归类为基础设施/评分失败，不进入质量分母。

取消持久化 `cancelRequested` 并停止调度。从未提交的意图无需联系 Worker 即可取消。可能已提交的意图通过原始键恢复，然后取消并观察，直到远端终态已知。全部调用结果明确后，Run 才变为取消。进程退出则停止并等待本地观察任务，不取消已接受的远端工作。Rank 仍要求单个编排器拥有者。

[Execution 事件读取](../../../../execution/backend/internal/app/service.go)在观察到终态后再次读取事件，覆盖空事件查询与状态查询之间提交完成的竞态。[Go 客户端](../../../../execution/backend/client/client.go)报告具名事件流错误，不把观察错误转成隐式取消。这同时保留终态进度和执行结果。

SQLite schema 22 与 PostgreSQL schema 3 增加调用记录、Run 执行配置、取消意图和派生事件唯一键。启动拒绝不具备受支持派发格式的活动远端 Run；已完成历史仍可读取。[后端参考](../../../../rank/backend/README.md)定义启动与共享核对配置。

## 考虑过的替代方案

**失败后生成另一个执行键。** HTTP 错误不能证明第一个请求是否已经开始。原始键能够找回已接受的调用，避免重复外部操作。

**通过远端提交取消所有已准备候选。** 会仅仅为了取消而启动工作。持久化可能已提交标记，能够区分尚未发送的意图和不确定的远端接受。

**从当前设置重建裁判配置。** 改变活动评测的含义，也可能使完成证据无法比较。准入快照保持恢复前后配置一致。

## 后果

[组装恢复快照](../../../../apps/rank-web/tests/evaluation-recovery.e2e.mjs)截断真实候选与裁判提交响应、杀掉 Rank，再验证每个阶段唯一的原始执行、唯一裁判/完成记录，以及保留的结果和费用。SQLite 与 PostgreSQL 测试覆盖响应丢失、ID/结果提交失败、重复进度、未知结果、配置变化，以及新编排器恢复取消。60 次 Trial 的打包评测通过真实 SSE（Server-Sent Events）路径核对每条候选与裁判完成事件。

缓存结果是 Execution 权威记录的投影，不是第二个运行时调度器。使用连接的候选模型由 [Agent 版本创建](2026-09-14-rank-frozen-model-selection.md)固定。完整运行时隔离、扩缩容指标和物理跨主机验收仍属于[生产提案](../../proposed/architecture/2026-09-14-rank-production-execution.md)。
