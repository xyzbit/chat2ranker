# Agent Note: 固定模型选择

Status: implemented

[English](2026-09-14-rank-frozen-model-selection.md) | 中文

## 问题

Worker 启动时读取连接默认值，会让已接受调用的模型发生变化。同一默认模型的空名称和显式名称还会形成不同并发分组。对话创建绕过连接校验时，可能保存无法使用或模型不明确的 Agent 版本。

## 决策

[Agent 配置](../../../../rank/backend/internal/app/service.go)在保存新版本时，从已验证连接解析省略的模型。模型名称去掉首尾空白后，与连接 ID 一起持久化。显式自定义模型即使不在发现的模型列表中也可使用。既没有显式模型、也没有默认模型的连接会被拒绝。修改连接默认值影响后续配置保存，不影响已有版本、Run 或 Response。

[对话命令](../../../../rank/backend/internal/app/control.go)在获取业务事务锁之前，使用相同的解析与协议检查。版本编辑继承不可变基础配置，再应用提供的字段；显式空模型会选择保存时的连接默认值。命令重放在读取当前连接设置前返回原始记录。事务内再次核对幂等性和会话拥有关系。

[Execution 协议](../../../../execution/backend/contract/model.go)要求存在模型连接 ID 时必须提供明确模型，并拒绝这两个标识中的首尾空白。Execution 准入和 Worker 派发都执行该规则。Worker 不替换连接默认值。因此 PostgreSQL 并发限制按一个精确的连接/模型组合统计；它不合并不同连接、不解析供应商别名，也不实现每分钟 token 限额。

对于已保存但未固定模型的连接型 Agent，Rank 拒绝新的评测以及试用/服务 Response；操作者需要选择明确模型并保存新版本。启动时拒绝受影响的活动 Rank 记录，不静默修改请求。未解析模型的排队 Execution 在启动运行时前失败。已完成记录仍可读取。不使用模型连接的原生 CLI（命令行界面）登录仍属于可信本地开发路径，不受连接/模型额度约束，也不是生产配额身份。

## 考虑过的替代方案

**Worker 启动时解析模型。** 连接默认值修改后，排队请求会改变含义，也无法与显式配置请求共享稳定模型额度。

**在 Execution 同时保存提交和解析后的模型配置。** 可以保留该处的 HTTP 幂等性，但如果 Execution 尚未接受请求，Rank 恢复时仍可能解析到不同默认值。在创建不可变版本之前解析配置，可以避免第二份配置，并更早固定取值。

## 后果

[组装模型解析场景](../../../../apps/rank-web/tests/model-resolution.e2e.mjs)启动打包后的 Rank 与 Execution 进程，检查表单创建、对话创建/版本编辑、默认值修改、显式名称、无效连接/协议拒绝、原始命令重放和未解析 Execution 拒绝。提交的快照记录外部可见模型。SQLite 与 PostgreSQL 应用测试覆盖固定版本，以及在评测或试用准入前拒绝旧的不明确 Agent。已有 PostgreSQL 并发 Worker 测试覆盖对应连接/模型预留分组。

此变更固定模型选择，不冻结供应商凭据或整个连接记录。凭据轮换和操作者管理的连接元数据仍由 Execution 负责。完整运行时隔离和生产容量验收仍属于[生产提案](../../proposed/architecture/2026-09-14-rank-production-execution.md)。
