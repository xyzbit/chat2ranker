# Agent Note: Production idempotency key build

Status: implemented

English | [中文](2026-08-29-production-idempotency-key-build.zh.md)

## Problem

The production Vite build transformed `globalThis.crypto?.randomUUID?.()` into code that invoked the method with an out-of-scope minified receiver. Clicking an A2UI run action failed locally with `E is not defined` or `x is not defined` before the command request reached Rank. Source-mode tests did not expose the production-only transform.

## Decision

Idempotency keys are generated by one helper that checks whether `crypto.randomUUID` is a function and then calls it directly; the timestamp fallback remains for environments without that API. Both command and legacy run requests use the helper. A unit test covers generated command keys, and packaged-browser acceptance intercepts the command endpoint to verify that clicking the production run card sends the POST without creating paid trials.

## Alternatives considered

**Tell users to refresh or change browsers.** A reload could replace an older bundle but could not repair the same broken transform in the newly built asset.

**Remove idempotency keys.** This would avoid the expression but allow duplicate runs when a request is retried, which is unacceptable for paid Agent execution.

## Consequences

Production run actions reach Rank with a stable idempotency key and retain duplicate-run protection. The helper also prevents the same build failure in the direct run endpoint.
