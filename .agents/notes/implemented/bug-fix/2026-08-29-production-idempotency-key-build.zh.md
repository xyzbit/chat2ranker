# Agent Note：生产环境幂等键构建修复

状态：已实现

[English](2026-08-29-production-idempotency-key-build.md) | 中文

## 问题

生产 Vite 构建会把 `globalThis.crypto?.randomUUID?.()` 转换成使用越域压缩变量作为方法接收者的代码。用户点击 A2UI 运行操作时，会在请求到达 Rank 前得到 `E is not defined` 或 `x is not defined`。只运行源码的测试无法暴露这个生产构建问题。

## 决策

通过一个统一函数生成幂等键：先判断 `crypto.randomUUID` 是否为函数，再直接调用；不支持该 API 的环境继续使用时间戳回退。命令接口和旧运行接口都使用这个函数。单元测试覆盖命令幂等键；发布包浏览器验收则拦截命令接口，确认点击生产运行卡会真正发出 POST，同时不会创建付费 Trial。

## 考虑过的替代方案

**让用户刷新或更换浏览器。** 刷新只能替换旧 Bundle，无法修复新构建产物中同样存在的错误转换。

**删除幂等键。** 这样虽然能避开表达式，但请求重试时可能重复创建付费运行，因此不可接受。

## 结果

生产运行操作能够携带稳定幂等键到达 Rank，同时继续防止重复运行。直接运行接口也不会再触发相同的构建错误。
