# Rank Web

English | [中文](README.zh.md)

This directory contains the Control DSH product assembly and conversation-first UI for chat2ranker.

The application owns only the browser entry point and DSH plugin composition. Experiment state, scheduling, results, and Runner lifecycle belong to the Go Rank service under [`rank/backend/`](../../rank/backend/README.md).

Complete chat instructions execute directly. When one or two required values are missing, Rank asks only for those values; structured UI is reserved for browsing candidates, reviewing many fields, bulk edits, and secrets. Form-to-chat handoff uses user-facing names and never exposes internal IDs or JSON.

The assembly mounts the Rank Control Host plugin, a persistent experiment Session, and the Rank experiment Skill. The Session uses tools to create, version, and select immutable dataset and Agent assets. The React UI renders optimistic chat messages, projected DSH tool activity over SSE, structured asset mentions, compact run summaries, and request-scoped A2UI cards. Control-agent replies use line-delimited Rank Message JSON objects for consistent summary, prose, list, fact, note, and code rendering; existing Markdown history remains readable, and the copy action exports either format as Markdown with explicit success or failure feedback and a legacy browser fallback. Run confirmation appears only after a run intent; experiment performance appears only after a data/results intent or its composer shortcut and compares all Runs and Agent versions in the current experiment. Single-Agent execution remains the default; one Agent multi-select replaces the current version when one item is selected and creates one RunGroup with one immutable child Run per selected version when several are selected, so existing Runner and Execution Service APIs stay single-task. Selected versions are applied when the picker closes, remain selected when reopened, and appear in a compact scrollable list with hidden scrollbars and an overflow fade; each row opens that exact version in the experiment workspace. These cards are durable conversation events rather than permanent page-tail widgets. The control Session can prepare dataset, rubric, Agent, non-secret model-connection metadata, Tool, Skill, comparison-Agent, and repeat-policy configuration through conversation, then render the result as reviewable A2UI. Provider secrets never enter the conversation and remain in the deterministic secure connection form. The model-connection workspace supplies official DeepSeek, MiniMax, GLM, OpenAI, Claude, and Kimi templates; choosing a provider narrows the model list and inherits its endpoint, protocol, price, source, and pricing note. Local per-model overrides stay under advanced settings, and Agent forms can reference only verified connections. Confirmation assets support separate detail and quick-switch actions. Runs with catalog- or connection-calculated cost use an approximate marker, while runs without provider cost or a matching price say that pricing configuration is missing and stay out of cost plots. An optional experiment workspace stays beside the conversation for dataset and Agent configuration, aggregate performance, run history, cases, logs, and artifacts; chat cards and plot points open the matching workspace entity directly. Dataset cases and Agent configuration can be edited there; each save creates and selects a new immutable version. Agent Tool and Skill references use searchable multi-select fields, accept explicit custom IDs, and can be submitted directly or projected into the Rank conversation. `rankd` submits tested agents to the independent Execution Service; they never run inside the Control DSH process.

The message parser repairs common model-generated quote, escape, and trailing-comma mistakes before using the readable legacy-text fallback.

Model selection merges the built-in catalog with models discovered through the saved connection, labels their source, supports search, and progressively discloses manual model IDs. Saved credentials can resynchronize the model list; a failed synchronization keeps the last successful list so a temporary Provider outage does not erase configuration.

Run the complete local assembly from the repository root with `pnpm rank:dev`. See [`rank/docs/local-acceptance.md`](../../rank/docs/local-acceptance.md) for keyless and real-provider acceptance flows.
