# Rank Web

`ManagementUI.jsx` owns shared page headings, errors, status pills, empty states, pagination, and inline confirmations. Pages import these directly rather than through another page module. Cursor availability, requests, and confirmation actions remain caller-owned.

This directory contains the Control DSH product assembly and conversation-first UI for agentkiln.

Agent playground opens as a conversation panel in Agent details or Deployment routes, with history independent of Rank control experiments. `rank_open_trial` opens the Agent panel with an optional unsent draft. [Playground semantics](../../rank/docs/agent-playground.md) describe version selection, history restoration, execution, and API limits. `RANK_TRIAL_BROWSER=1 node --test --test-name-pattern='Agent playground' tests/stage5-e2e.test.mjs` verifies desktop/mobile flows using isolated services and keyless CLI fixtures.

`ConversationDock` shares placement, mode tabs, focus handling, and dismissal between Rank and trials. Wide screens reserve space beside the page; narrow screens use a drawer and mobile uses the full screen. Agent details separate Configuration and Evaluation tabs: configuration owns runtime settings, always-visible tools and Skills, version creation, and a link to a separate addressable comparison page; evaluation owns independently saved family dataset defaults and selected-version records. Switching tabs preserves unsaved defaults. Evaluation opens a new Rank draft; Publish resolves the viewed version through the [deployment entry flow](../../rank/docs/release-policy.md#review-and-publish). Deployment navigation opens a list with addressable detail links.

The application owns only the browser entry point and DSH plugin composition. Experiment state, scheduling, results, and Runner lifecycle belong to the Go Rank service under [`rank/backend/`](../../rank/backend/README.md).

The product calls serving targets Endpoints; API paths and stored Deployment identifiers retain their existing names. Endpoint details display the published version, execution limits, and release decisions without a visibility toggle. Trial entry belongs to Agent details.

Integration opens a right drawer: select an existing API key and paste its retained value, or create one inline, then copy an executable cURL or JavaScript command. Key names default to a local timestamp; endpoint and operation permissions default to all existing choices and remain editable. This is a fixed allowlist, not access to future endpoints. New or pasted plaintext stays only in the open drawer; copied commands contain the key, while Copy for Agent contains only an environment-variable reference. Both development and packaged servers forward same-origin `/v1/` requests to Rank.

The single-row sidebar footer opens Settings and links to the local documentation center at `#/docs`. Documentation covers product workflow, quick integration, additional instructions, caller functions, streaming, Responses-capable chat tools, runnable demos and [invocation feedback](../../rank/docs/response-feedback.md). Copy to Agent links a directly readable Markdown API reference. Shared examples run through the keyless serving acceptance test.

Integration and Examples offer standalone headlines and chat ZIPs with an endpoint-specific `.env.example`, dependencies and a bilingual startup tutorial. An explicit source allowlist excludes credentials and local artifacts. Documentation carries the selected endpoint through topic links and distinguishes rejected requests from recorded execution failures. Downloads use a lazy-loaded ZIP module in development and built distributions.

Complete chat instructions execute directly. When one or two required values are missing, Rank asks only for those values; structured UI is reserved for browsing candidates, reviewing many fields, bulk edits, and secrets. Form-to-chat handoff uses user-facing names and never exposes internal IDs or JSON.

[Conversation configuration](../../rank/docs/conversation-configuration.md) covers direct commands and durable actions that open shared settings, credential, Webhook and integration forms inside chat. Secret forms discard plaintext on close and do not append it to conversation history.

The assembly mounts the Rank Control Host plugin, a persistent experiment Session, and the Rank experiment Skill. The Session uses tools to create, version, and select immutable dataset and Agent assets. The React UI renders optimistic chat messages, projected DSH tool activity over SSE, structured asset mentions, compact run summaries, and request-scoped A2UI cards. Control-agent replies use line-delimited Rank Message JSON objects for consistent summary, prose, list, fact, note, and code rendering; existing Markdown history remains readable, and the copy action exports either format as Markdown with explicit success or failure feedback and a legacy browser fallback. Run confirmation appears only after a run intent; experiment performance appears only after a data/results intent or its composer shortcut and compares all Runs and Agent versions in the current experiment. Single-Agent execution remains the default; one Agent multi-select replaces the current version when one item is selected and creates one RunGroup with one immutable child Run per selected version when several are selected, so existing Runner and Execution Service APIs stay single-task. Selected versions are applied when the picker closes, remain selected when reopened, and appear in a compact scrollable list with hidden scrollbars and an overflow fade; each row opens that exact version in the experiment workspace. These cards are durable conversation events rather than permanent page-tail widgets. The control Session can prepare dataset, rubric, Agent, non-secret model-connection metadata, Tool, Skill, comparison-Agent, and repeat-policy configuration through conversation, then render the result as reviewable A2UI. Provider secrets never enter the conversation and remain in the deterministic secure connection form. The model-connection workspace supplies official DeepSeek, MiniMax, GLM, OpenAI, Claude, and Kimi templates; choosing a provider narrows the model list and inherits its endpoint, protocol, price, source, and pricing note. Local per-model overrides stay under advanced settings, and Agent forms can reference only verified connections. Confirmation assets support separate detail and quick-switch actions. Runs with catalog- or connection-calculated cost use an approximate marker, while runs without provider cost or a matching price say that pricing configuration is missing and stay out of cost plots. An optional experiment workspace stays beside the conversation for dataset and Agent configuration, aggregate performance, run history, cases, logs, and artifacts; chat cards and plot points open the matching workspace entity directly. Dataset cases and Agent configuration can be edited there; each save creates and selects a new immutable version. Agent Tool and Skill references use searchable multi-select fields, accept explicit custom IDs, and can be submitted directly or projected into the Rank conversation. `rankd` submits tested agents to the independent Execution Service; they never run inside the Control DSH process.

The message parser repairs common model-generated quote, escape, and trailing-comma mistakes before using the readable legacy-text fallback.

Assistant avatars use a solid blue circle with white eyes. Idle eyes glance left and right; a mouse within 140 CSS pixels takes over the gaze. Leaving that area, scrolling, or losing window focus restores idle motion. Reduced-motion preferences disable both idle animation and mouse tracking; touch input does not move the eyes.

The default floating companion shares this face and gaze behavior. Its launcher opens the existing assistant drawer; enablement, custom sprite imports, and the working-status dot remain owned by the companion settings.

Rank, trial, and recent-session regions hide their scrollbars and fade only edges with additional content. Other scrollable content exposes a thin thumb on hover or keyboard focus, with no track background or border. Keyboard scrolling remains available; conversation updates follow the tail only when the reader is already near it. Forms use solid backgrounds, while fixed mobile navigation uses subtle translucency. Native modal dialogs contain focus and restore it on dismissal; searchable model menus use the browser top layer and support arrow keys, Enter, and Escape. See the [UI interaction decision](../../.agents/notes/implemented/feature/2026-09-10-rank-ui-interaction.md).

With the local acceptance conversation available, `playwright-cli run-code --filename apps/rank-web/tests/ui-layout.browser.js` verifies the assembled pages, desktop/mobile layout, language switching, modal focus, conversation scrolling, and model selection without submitting forms or model requests. Screenshots are written to `output/playwright/`.

With a configured local Rank conversation open in Playwright CLI, `playwright-cli run-code --filename apps/rank-web/tests/assistant-avatar.browser.js` checks gaze interaction and saves desktop/mobile screenshots under `output/playwright/` without sending model requests.

`ModelField` supplies one editable model selector for initialization, Agent and connection editors, and system-model bindings. The input accepts arbitrary model IDs; its arrow opens deduplicated catalog and connection suggestions, typing filters them, and arrow keys, Enter, and Escape select or dismiss without discarding typed text. The browser popover layer keeps menus visible inside dialogs and scroll regions. Saved credentials can resynchronize the model list; a failed synchronization keeps the last successful list so a temporary Provider outage does not erase configuration.

Settings groups saved Model connections and Local connections in one tabbed Connection section. Tab changes retain connection drafts and discovery results. Section spacing and headings replace repeated divider lines. `playwright-cli run-code --filename apps/rank-web/tests/settings-connections.browser.js` checks desktop/mobile tabs, direct model input, dropdown and keyboard selection, binding payloads, draft retention, and menu placement with keyless browser responses.

Run the complete local assembly from the repository root with `pnpm rank:dev`. See [`rank/docs/local-acceptance.md`](../../rank/docs/local-acceptance.md) for keyless and real-provider acceptance flows.

When no system model is bound, first-use setup offers Local connections and Connection setup tabs. Optional discovery selects the local tab when candidates exist, otherwise manual setup stays selected; an in-progress draft is never displaced by a late scan. Both tabs accept a typed model name with catalog suggestions. "Start conversation" imports or saves the selection, verifies that exact model, and binds Control and Judge. "Set up later" dismisses setup in that browser and opens the platform. Settings exposes "Rediscover" and marks imported candidates as added; imported connections use the existing edit-and-verify form. Discovery has a five-second browser timeout, and failure never disables manual configuration or dismissal. Supported sources and credential handling belong to the [Execution backend](../../execution/backend/README.md).

`playwright-cli run-code --filename apps/rank-web/tests/local-model-discovery.browser.js` checks setup tabs, editable models, preserved drafts, explicit binding, rediscovery, and failed-scan dismissal at desktop/mobile sizes against a local assembly. Browser routes supply keyless connection responses; the service discovery and import snapshot runs through real Rank and Execution processes in `node --test tests/stage5-e2e.test.mjs` from this directory.

All single-choice fields use `SelectField`, backed by Radix Select. Pages supply `value`, `onValueChange`, and labeled options; the shared component owns empty and disabled choices, required-field validation, keyboard navigation, focus restoration, and modal-aware menu placement. Editable model suggestions and searchable model discovery keep their specialized inputs. `theme.css` owns visual tokens, `controls.css` owns shared control appearance and focus, and `ui-config.js` owns menu positioning. Language choices live in `i18n.js`; provider and protocol choices live in `model-connections.js`. Form drafts remain local and model catalogs come from the service. See the [shared controls decision](../../.agents/notes/implemented/feature/2026-09-10-rank-shared-controls.md).

Shell language controls share one translation-icon component with a localized tooltip and accessible name. `playwright-cli run-code --filename apps/rank-web/tests/ui-controls.browser.js` checks the assembled settings and filters, desktop/mobile layout, modal ownership, nested Escape behavior, disabled placeholders, and selectable empty filters without saving forms. `playwright-cli run-code --filename apps/rank-web/tests/deployment-switcher.browser.js` covers deployment navigation and language toggling.

Agent details edit shared default development and regression datasets. Deployment and conversation share the [release workflow](../../rank/docs/release-policy.md): comparable development results, replaceable datasets, regression enabled by default, and durable progress. Failed tasks expose reasoned override in details; release history preserves attempts and frozen decisions. `RANK_RELEASE_BROWSER=1 node --test tests/stage5-e2e.test.mjs` runs the browser flow against temporary services; screenshots stay under `output/playwright/`.

The control-host forwards `EXECUTION_SERVICE_TOKEN` when resolving its system model from Execution, in addition to `RANK_CONTROL_TOKEN`. These server environment values are never supplied to the browser. See [Execution configuration](../../execution/backend/README.md#durable-execution-modes).

Artifact previews preserve the Execution response encoding: UTF-8 text is displayed directly; binary bytes use base64, with download available only for untruncated responses. See [artifact evidence](../../.agents/notes/implemented/architecture/2026-09-15-execution-failure-evidence.md).

The control-host authorizes public conversation and stream requests through Rank’s identity endpoint. A non-loopback listener requires management authentication on Rank. `RANK_AUTH_TIMEOUT_MS` defaults to 3000 and bounds identity checks; unavailable authorization returns 503 before a new turn starts. `RANK_MANAGEMENT_ORIGIN` sets the public HTTP(S) origin behind a TLS gateway, matching Rank. Browser credentials are forwarded only to the identity endpoint; Rank tool calls use the separately scoped control token. See [management access](../../rank/backend/README.md#management-access).

The browser verifies `/api/identity` before mounting workspace views. Unauthenticated visitors see an account/password form with login errors and retry; authenticated operators can sign out in Settings. Refresh retains the HttpOnly session cookie and current page. Management 401 responses, focus checks and a one-minute identity check return expired sessions to login. Passwords and session IDs never enter browser storage or conversation. The control host forwards the cookie only to Rank identity verification. See [management access](../../rank/backend/README.md#management-access) for lifetime and deployment limits.
