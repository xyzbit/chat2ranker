# Execution backend

English | [中文](README.zh.md)

This Go module is a reusable execution control plane. It produces:

- `executiond`: versioned HTTP API, idempotent execution records, lifecycle control, Repository access, Executor selection, and Artifact authorization.
- `execution-worker`: one immutable Harness Adapter invocation with a private workspace and Harness Home.

The public `contract` and `client` packages define Rank integration; `harness` and `artifacts` define adapter APIs. Domain and application code depend on Repository and Executor interfaces. SQLite runs a bounded local worker pool. PostgreSQL uses River OSS v0.47.0 with separate API and worker roles; both use the selected Executor. The OpenSandbox adapter runs packaged DSH or the deterministic Harness remotely, with persisted ownership and bounded cleanup.

Harness integrations implement the public `harness.Adapter` interface and register by stable Runner type. The built-in registry contains the deterministic Demo adapter, the first-party DSH adapter, native event-aware adapters for Claude Code, Codex, and Hermes, and a shell-free deployment adapter for Pi. Codex consumes ephemeral `exec --json` runs, Claude Code consumes non-persistent `stream-json` runs, and Hermes consumes its usage report. Native Codex and Claude Code runs reuse the invoking user's CLI authentication while keeping each task workspace and Harness home isolated. Default Codex runs ignore user configuration, Claude Code runs in safe mode, and both receive the frozen Agent model as an invocation flag; a Codex model connection instead generates a private per-run provider configuration.

`/v1/model-catalog` supplies official connection defaults for DeepSeek, MiniMax, Zhipu GLM, OpenAI, Claude, and Kimi: endpoint, protocol, selectable model IDs, USD-per-million-token defaults, pricing notes, source URL, and refresh date. MiniMax, Zhipu, and Kimi default to their official mainland-China OpenAI-compatible endpoints; international endpoints remain available as custom connections. Official CNY rates are normalized to USD estimates with the catalog's fixed `CNY 7.00 = USD 1` conversion and disclosed in every affected model's pricing note, so cross-provider plots retain one currency. Chat Completions, Responses, and Anthropic Messages connections are verified with their native model-list and minimal inference requests. A successful model-list refresh replaces discovered models; a failed refresh preserves the last successful list, and a provider without `/models` can still verify an explicit model through the minimal request. A connection can override any inherited rate without changing the local catalog. Cost resolution remains provider-reported actual cost, then connection override, then catalog default; missing usage or price stays unknown.

Model connections are managed through `/v1/model-connections`, and `/v1/model-catalog` exposes built-in provider endpoint, model, and default-price metadata. A connection can override prices for its models. Metadata is stored in the execution Repository, while API keys are stored separately in the local credential directory or encrypted PostgreSQL credential table and are never serialized into execution specifications, events, or artifacts. Verification synchronizes `/models` when available and performs one minimal request using the selected protocol. DSH accepts all three protocols, Hermes accepts Chat Completions, Codex accepts Responses, and Claude Code uses its own CLI authentication.

Execution cost uses provider-reported actual cost first, then the matching connection price, then the built-in catalog price. Calculated costs retain a frozen price snapshot and are marked as estimates. If usage or a matching price is absent, cost remains unknown instead of using a different provider's price or an invented estimate.

`GET /v1/executions/{id}/events` exposes the durable per-execution event log as SSE. Each event has a monotonic sequence, attempt number, type, status, optional data, and timestamp. Reconnecting clients pass `Last-Event-ID` or `?after=` and replay persisted lifecycle and Harness progress before following live events.

Command stdout progress preserves emitted whitespace and text chunks. Codex and Claude Code adapters keep raw protocol output in artifacts and emit only the parsed assistant answer as `harness.output`; consumers must not present protocol JSON as conversation text. Progress timing follows the adapter and may be a complete answer rather than token deltas.

`Spec.modelConnectionId` requires a nonempty, trimmed `Spec.model`. Rank resolves connection defaults when saving Agent versions; direct Execution callers resolve defaults before submission. Workers use the recorded name even if the connection default changes. Missing or whitespace-aliased model selections are rejected before admission.

The DSH adapter starts Node with `--expose-internals`, required by the CLI configuration-watching service in packaged headless profiles. Both prompt and structured-history invocation paths use this startup flag.

Structured Agent input uses exactly one of `prompt` or `messages`. The `/v1/runtimes/{harness}` capability `structuredHistory` identifies adapters that accept ordered user/assistant/tool messages. Unsupported history rejects before admission; DSH history uses the [private history runner](../../apps/execution-runtime/README.md). Command adapters opt in with `{input}`. Codex, Claude Code and Hermes are prompt-only.

## Durable execution modes

Go 1.26.0 is required. Without `EXECUTION_DATABASE_URL`, `executiond -role all` uses SQLite. With PostgreSQL, `-role api` accepts requests and serves durable events; `-role worker` consumes River jobs; `-role all` combines them. Run `-migrate` explicitly before serving. Schema readiness is recorded only after application DDL and every River migration succeeds. PostgreSQL enum migrations commit by version under one migration lock; wrapping all River migrations in one transaction is unsupported.

`-database-timeout` defaults to `5s` and bounds PostgreSQL pool acquisition, query I/O and application transactions. Earlier caller deadlines win; synchronous serving and SSE retain their own lifetimes. Raw dependency deadlines return HTTP 503 `dependency_timeout`; clients must preserve request identity because a timeout does not prove a write rolled back. For longer explicit migrations, run `-migrate -database-timeout=45s`. See [database deadline semantics](../../.agents/notes/implemented/architecture/2026-09-15-postgres-deadlines.md).

PostgreSQL startup requires `EXECUTION_SERVICE_TOKEN` of at least 24 characters and `EXECUTION_CREDENTIAL_KEY`, a base64-encoded 32-byte AES-GCM key. The master key is deployment state: preserve it with database backups and supply it to the API and workers. Every HTTP route except `/v1/health` requires the service bearer token when configured; `/v1/capacity` also accepts the optional read-only `EXECUTION_CAPACITY_TOKEN`. Internal system-model credential resolution additionally requires `RANK_CONTROL_TOKEN`. Rank and control-host use `EXECUTION_SERVICE_TOKEN` for these calls.

An idempotency key identifies one immutable input. JSON object formatting and equivalent decimal notation do not affect identity; array order and distinct values do. The Execution record, first event and River job commit together; jobs contain only the execution ID. Runtime limits are resolved at submission and stored independently from the input used for idempotency comparisons. A worker records its identity and actual release version when starting. Result publication and River acknowledgement share a transaction. Durable progress requires the current running attempt; cancelling or terminal attempts cannot publish late progress.

Queue wait is bounded separately from runtime duration: `-queue-timeout` defaults to `5m` and must be at least `1ms`; `Spec.queueTimeoutMs` may shorten it. Admission persists `queueExpiresAt` at millisecond precision. Replay and restart preserve it. API reconciliation emits `execution_queue_expired` with attempt zero for overdue queued work, while Worker claim checks prevent late startup. Running work uses its separate timeout. Overdue queued work appears as `expired` in capacity and does not request workers. Missing deadlines fail as `execution_limits_missing`; upgraded queued records do not receive fresh waiting time. See [queue deadline semantics](../../.agents/notes/implemented/architecture/2026-09-15-execution-queue-deadline.md).

Queued cancellation prevents runtime startup. Running cancellation enters `cancelling` and becomes `cancelled` only after runtime shutdown returns. Unconfirmed forced termination produces failure and retains the workspace. Started executions whose owner disappears are reported as `execution_outcome_unknown` after their recorded lifetime; delivery retries do not authorize another model/tool invocation. A terminal-delivery reconciler closes records whose River delivery ended without publishing an application outcome. Local restart also refuses to replay started invocations. Started attempts expose `runtimeCleanupPending`; an unknown failure retains model/tenant capacity until attempt-fenced shutdown confirmation. PostgreSQL schema 7 and SQLite schema 10 preserve this state across upgrades. The local adapter has no automatic cleanup recovery for lost owners; see [cleanup ownership](../../.agents/notes/implemented/architecture/2026-09-14-execution-runtime-cleanup.md).

`-online-slots` and `-evaluation-slots` bound each worker process; a request with `metadata.responseId` uses the online queue. `-max-queued` bounds admission and returns HTTP 429 when full. PostgreSQL `-max-model-concurrent` and `-max-tenant-concurrent` additionally bound running/cancelling records across worker replicas. Quota-blocked jobs snooze before runtime startup. These are concurrency limits, not provider token-per-minute limits. Deployments must resolve model names and trusted tenant metadata consistently.

`GET /v1/capacity` exposes aggregate online/evaluation demand for one homogeneous worker configuration. `active` counts durable running/cancelling records; `ready` allocates remaining global quota virtually across eligible queued work. Capability/delivery/quota/resource blocking and terminal `cleanupPending` are separate counts. Enabled queues expose `demand = active + ready`, `slotsPerWorker` and `oldestReadyWaitSeconds`. This is next-poll demand, not measured live slots or provider throttling. API/worker backend, capabilities, slots and limits must match. See [capacity semantics](../../.agents/notes/implemented/architecture/2026-09-15-execution-capacity.md) and the [bounded scaling lab](../../rank/deploy/k8s/README.md).

`-worker-timeout`, `-cleanup-grace`, `-persistence-timeout`, `-poll-interval`, `-rescue-after`, `-reconcile-interval`, and `-shutdown-grace` control execution, recovery and draining. River's rescue delay must exceed execution, cleanup and persistence limits. SIGTERM stops new claims and drains until the shutdown deadline, then cancels active work and waits for bounded cleanup. Keep runtime limits consistent across API and worker releases. The local executor is for trusted workloads; process groups are not a sandbox or a guarantee against arbitrary detached descendants.

The Go client's `RunWithEvents` returns observer errors without cancelling accepted work; explicit cancellation uses `Cancel`. Named SSE failure frames are errors. Event streaming rereads events after observing terminal state before closing, so completion racing an empty query cannot hide the final event.

## Model request budget

For the first-party DSH adapter, `-max-model-requests` defaults to 32 total model-stream attempts per Execution. `Spec.maxModelRequests` may tighten that cap; zero selects the service default. Admission freezes the resolved value separately from request identity, and replay or changed defaults never reset it. SQLite schema 10 and PostgreSQL schema 7 persist it; worker protocol 3 carries it to the packaged runtime. Upgrade API and Workers together after explicit PostgreSQL migration. Old queued DSH work lacking a resolved budget fails before startup instead of acquiring a fresh allowance.

The runtime's `llm/stream` listener reserves a slot before dispatch. Ordinary calls, retries, compaction and other DSH auxiliary model calls share one process-wide counter. At exhaustion it raises `execution_model_budget_exhausted`; it does not retry the whole invocation. Unsupported adapters, including custom command overrides, advertise no `modelRequestBudget` capability and reject an explicitly requested budget. A Worker lacking support cannot claim budgeted work. This is a DSH application limit, not an HTTP gateway, token/cost allowance, tenant RPM/TPM quota or restriction on native tools making their own network calls. See [the decision](../../.agents/notes/implemented/architecture/2026-09-15-execution-model-budget.md).

## Shared model-account limits

PostgreSQL model quotas group verified connections consuming the same provider account. API and Workers require a dedicated callback signing key and a runtime-reachable permit URL. DSH reserves before each actual provider attempt; unsupported harnesses and SQLite reject quota-bearing work. RPM/TPM group edits, estimates, output caps, timeout flags and the runnable snapshot are documented in the [quota example](../../rank/examples/model-quota/README.md). The runtime callback accepts only invocation identities, never the ordinary service token. Upgrade the API, Worker and Sandbox runtime together with schema 7 and worker protocol 3.

## OpenSandbox runtime

Set `-executor=opensandbox`, `-sandbox-endpoint` (HTTP(S), including `/v1`), `-sandbox-scope` (stable deployment ownership) and `-sandbox-image` (an immutable SHA-256 image). Supply `EXECUTION_SANDBOX_API_KEY` privately. API and workers must select compatible execution backends; mismatches wait without a local fallback. The image must include the packaged DSH worker, the `node` account at UID/GID 1000 and the protected init from [the sandbox image](../../rank/deploy/k8s/sandbox.Dockerfile).

`-sandbox-cpu` accepts positive cores or millicores; `-sandbox-memory` accepts positive integer bytes or quantities such as `512Mi`. `-sandbox-request-timeout` bounds management/file requests, and `-max-artifacts` bounds retained file count. Each attempt stores its remote allocation in `runtime`; `externalHandle` still identifies its worker owner. Cleanup verifies ownership and deletion before releasing capacity. Missing creation responses are not retried; delayed discovery can recover the resource, while an empty search cannot establish that a late creation is absent.

`-sandbox-pool`, `-sandbox-capacity-cpu` and `-sandbox-capacity-memory` are required exclusive service budgets shared through the Execution database. Startup verifies stored configuration; `-configure-sandbox-pool` explicitly updates it and exits. Update API/Worker startup flags to match after a budget change. Target changes require drained queued/active/unconfirmed work. Admission freezes `runtimePlan`, including image and resource limits; CPU must resolve to integer millicores. Resource waits keep attempt zero and appear as `resourceBlocked` in capacity. See [resource admission](../../.agents/notes/implemented/architecture/2026-09-15-execution-runtime-pool.md).

Set `-sandbox-egress-policy` to a JSON object such as `{"allow":[{"protocol":"tcp","cidr":"192.0.2.10/32","port":443}]}`, or supply `EXECUTION_SANDBOX_EGRESS_POLICY`. Empty configuration denies new external connections; zero port allows all ports of that protocol. The immutable runtime plan stores canonical rules, and incompatible Workers cannot claim it. The protected image requires explicit policy and installs IPv4/IPv6 kernel filters before starting execd, then drops network-administration capabilities. DNS requires an explicit resolver allowance. See [the egress decision](../../.agents/notes/implemented/architecture/2026-09-15-sandbox-egress.md) for deployment prerequisites and limitations.

The adapter supports DSH and the deterministic Harness. It sends no volume or sidecar requests, requires a same-origin authenticated command proxy and uses a protected container deadline independently of the lifecycle service. The dedicated lab verifies bounded writable storage and transport egress; arbitrary hostile-code isolation and complete production policy remain unverified; server deployments must not inject host mounts or unsolicited sidecars. Configuration, ownership and safety rationale are recorded in [the decision](../../.agents/notes/implemented/architecture/2026-09-15-execution-opensandbox.md); [the local experiment](../../rank/deploy/k8s/README.md) supplies runnable setup and verification.

## Artifact storage

Filesystem artifacts remain the lightweight default. Set `EXECUTION_S3_ENDPOINT`, `EXECUTION_S3_BUCKET`, `EXECUTION_S3_ACCESS_KEY`, and `EXECUTION_S3_SECRET_KEY` to use an existing S3-compatible bucket; `-s3-region` configures signing and `-s3-tls=false` permits an explicit local HTTP lab. Worker files are staged locally, uploaded under execution/content-digest keys, and referenced with SHA-256 and size before result publication. `-max-artifact-bytes` bounds each file. Failed upload fails the execution without replaying its model call. Valid worker failure responses also publish observed output, usage and artifacts before terminal failure; a nonzero exit alone cannot turn a known worker error into an unknown outcome. The observed reply/usage and each confirmed artifact reference are persisted progressively; `result` may exist on an active or failed execution and only `status` determines success. See [failure evidence](../../.agents/notes/implemented/architecture/2026-09-15-execution-failure-evidence.md). Unreferenced successful uploads require an operator retention policy; automatic orphan collection is not implemented.

The API authenticates artifact access against the execution's recorded references and reads through the configured store. Local reads reject directory traversal and symlink escape. The S3 adapter supports URLs with a maximum 15-minute lifetime for authenticated consumers; the HTTP artifact route currently proxies content rather than exposing a signed-link route. S3 storage does not preserve process memory or turn the worker's workspace into shared storage.

See the [runnable lifecycle example](../../rank/examples/execution-lifecycle/README.md) for keyless SQLite, PostgreSQL/River and S3 verification, and the [delivery decision](../../.agents/notes/implemented/architecture/2026-09-14-execution-river-delivery.md) for ownership and recovery rationale.

Artifact responses include `encoding` (`utf-8` or `base64`) and `truncated`; the one-MiB preview limit applies to bytes before encoding. Decode binary content before checking its digest. The [failure-evidence decision](../../.agents/notes/implemented/architecture/2026-09-15-execution-failure-evidence.md) defines partial-result and artifact authorization semantics.

## Local connection discovery

`POST /v1/local-model-connections/discover` reads optional configuration on the Execution host without contacting providers or saving connections. Codex discovery reads the user-level `config.toml` under `$CODEX_HOME` or `~/.codex`: explicit model, selected provider, endpoint override, environment-key reference, direct token, or API key in `auth.json`; see the [Codex configuration reference](https://developers.openai.com/codex/config-reference/). Files must be regular and at most 1 MiB. Source failures return credential-free issues alongside usable candidates. Profile composition, project settings, command authentication, subscription/OAuth credentials, and extra request headers require manual configuration.

DSH discovery reads `llm-pi-ai.providers`, `llm-deepseek`, and `agent-default-model` from `$DSH_HOME/settings.yaml` or `~/.dsh/settings.yaml`. Each provider produces one candidate, using its saved default model or its first configured model. Explicit protocols take precedence; OpenAI, Anthropic, MiniMax, MiniMax CN, and DeepSeek also support DSH's protocol defaults. Pi-ai endpoints remain explicit; the first-party DeepSeek route uses its configured endpoint, `DEEPSEEK_BASE_URL`, or the official endpoint. Credentials resolve from inherited environment, then `.credentials.yaml`, then the DSH home's `.env`. Both flat credential maps and version-1 `refs` are supported; plugin-owned `records` and grants are never imported. Other implicit catalog values require manual configuration.

`POST /v1/local-model-connections/{id}/import` accepts an optional `model` override, re-reads the candidate, and saves its key only in the credential store. Matching protocol, endpoint, model, and credential values reuse an existing connection, including manually created connections. Concurrent imports are serialized. Changed source endpoint or model metadata invalidates the candidate ID; a changed key or selected model creates a separate connection. Import never verifies or binds a system model. Rediscovery reports existing connection IDs without updating saved configurations.
