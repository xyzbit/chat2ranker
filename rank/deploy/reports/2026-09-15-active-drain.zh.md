耗时来自本地观察 Pod 删除与容器终态，包括 Kubernetes 上报延迟。watch 保留精确 Pod UID，只有对象消失不能通过。每个执行只有一次 running 事件和一次终态事件。重复原请求返回原 ID、状态及尝试次数。快照通过真实 API 和 DSH 进程、确定性本地模型核对这些结果。

验证器恢复两个 Worker 和原滚动更新注解，等待所属请求收敛，关闭 watch/转发进程，移除模型 fixture。通过的运行没有清理错误。实验配置为每个 Worker 一个在线槽位、60 秒调用上限、15 秒排空宽限期、两秒运行时清理、三秒持久化，以及 25 秒 Pod 终止宽限期。

这是单笔记本上的手动缩容与滚动替换结果，不代表 KEDA 自动缩容选择、物理节点故障、供应商容量，或任意长调用均不中断。退出码零表示 Worker 干净停止；业务成功仍以 API 的持久调用状态为准。复现入口见[活跃排空教程](../k8s/README.md#active-worker-drain-experiment)。
