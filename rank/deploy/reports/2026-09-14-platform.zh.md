## 环境与范围

独立的单节点 `rank-dev` minikube 集群运行 PostgreSQL、SeaweedFS、Execution API、两个 DSH Worker、Rank API、持久化中控、Nginx 和确定性模型服务。节点容器配置为 4 CPU、4 GiB；Kubernetes 可分配资源反映更大的 Docker 虚拟机，不是可用容量保证。[Execution 报告](2026-09-14-execution.zh.md)记录依赖镜像和 fixture 扩容证据。平台使用 Linux arm64、Node 24.21.0、Go 1.26.0 和 River OSS 0.47.0。Worker 限制为 1 CPU/768 MiB、一个在线槽位和一个评测槽位、60 秒执行超时与 75 秒拥有者恢复阈值。

## 观察结果

| 场景 | 结果 |
| --- | --- |
| 网关路由 | 管理访问需要 Basic 鉴权；公开 Response 需要服务密钥；内部命令返回 404；鉴权后的静态页面返回 200。 |
| 每日热点客户端 | 经公开端点和真实 DSH 进程完成，带有注入来源快照的编号引用。 |
| OpenAI SDK 聊天与 SSE | 两轮保留名字、偏好及时间预算；流式文本与完成结果一致，Agent 版本保持固定。 |
| Agent 试用 | 直接试用经 DSH 完成，PostgreSQL 的家族/精确版本及仅直连筛选返回同一会话。 |
| 结构化历史 | 持久 Execution 输入包含独立的 user/assistant/user 消息。 |
| 持久证据 | S3 中的 stdout 可读取；从倒数第二个游标重放终态 SSE，恰好返回最后一个事件。 |
| Rank/中控替换 | 旧回复可读取且聊天可继续；中控会话元数据报告恢复及保留的事件数量。 |
| 零 Worker 与重启 | 零 Worker 时接受的后台 Response 跨 Rank 重启保留，扩容后以第一次尝试完成。替换 Worker 后旧 stdout 保持一致。 |

模型服务实现真实 HTTP/流式协议，但返回确定性 fixture 文本，无需外部模型密钥。每日热点场景不抓取实时新闻。测试端点采用显式人工覆盖发布，因此本次运行不证明评测/回归质量或发布策略覆盖。中控会话保留通过恢复元数据检查，不表示 `/session` 返回完整对话内容。

浏览器验证发现并修复了试用历史查询的 PostgreSQL 布尔参数编码错误。回归测试先复现失败，再在 SQLite 与真实 PostgreSQL 上通过；打包试用快照在两个数据库上重放通过。打包端点/发布快照在 PostgreSQL 上通过。浏览器截图摘要记录在机器可读证据中；原图留在本地验收产物目录。

## 限制与后续验收

实验验证一台笔记本上的进程分布，不验证物理主机扩容、生产吞吐或高可用。实验共用可信数据库角色和管理 Basic 凭据，不证明生产租户隔离或完整 Harness 隔离。Chrome 在 1440×1000 下验证 Agent 详情、两轮试用与刷新恢复、前往已有端点、接入面板、设置和文档导航；本轮未覆盖所有浏览器交互或移动视口。[生产设计](../../../.agents/notes/proposed/architecture/2026-09-14-rank-production-execution.zh.md)保留隔离运行时、有效扩容指标、有界自动扩缩容及有限额真实供应商/跨主机验证等独立工作。
