# Sandbox 资源准入实验 — 2026-09-15

[English](2026-09-15-runtime-pool.md) | 中文

[机器可读报告](2026-09-15-runtime-pool.json)记录镜像、预算与实际结果。单台笔记本上的两个 minikube Worker Pod 控制独立 Docker Sandbox 容器。模型提供方是确定性的，DSH 进程、生命周期服务、数据库及容器限制均真实运行。

| 阶段 | 分配的资源池预算 | 实际结果 |
| --- | --- | --- |
| CPU 受限 | 500 毫核、2 GiB | 三个不同租户/模型连接均以一次尝试完成，最多观察到一个存活 Sandbox。 |
| 内存受限 | 2 CPU、512 MiB | 内存成为限制因素时保持相同行为。 |

每个容器配置 500 毫核与 512 MiB，并通过 Docker 检查核实。排队工作保持 attempt 为零且没有运行时。资源阻塞不增加额外可执行需求；资源池空闲时，仍有一个等待请求可启动。验证器恢复原始 2-CPU/2-GiB 预算，并移除临时模型服务。

SQLite 和真实 PostgreSQL 测试覆盖并发准入、未知结果预留、目标变更拒绝、重复服务预算、超规格请求及运行中降低预算。Executor 测试验证排队规格不随默认值变化，不同镜像无法领取任务。两种数据库模式均通过包含冻结资源字段的打包远程快照，资源准入与需求投影也通过竞态检查。

分配预算不是物理空闲资源测量。其他应用需要预留余量，独立 Execution 数据库或直接生命周期客户端不能重复使用同一预算。这些实验不证明物理主机扩容、磁盘/出口限制或生产可用性。命令和前提见[教程](../k8s/README.md#sandbox-resource-budget-experiment)，拥有关系与更新规则见[决策记录](../../../.agents/notes/implemented/architecture/2026-09-15-execution-runtime-pool.md)。
