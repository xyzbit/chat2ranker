# Sandbox 有界存储 — 2026-09-15

[English](2026-09-15-sandbox-storage.md) | 中文

专用 Docker 运行时通过原生进程存储耗尽实验和 minikube 完整平台的七项检查。[机器可读证据](2026-09-15-sandbox-storage.json)记录精确的运行时/服务镜像、源文件摘要和受保护寿命结果。测试使用真实 DSH 进程与确定性本地模型，不调用外部模型。

| 检查 | 观察结果 |
| --- | --- |
| 输入、工作区和产物共享 128 MiB | 跨三个目录的累计写入触发 `ENOSPC`；释放文件后可以重新写入。 |
| 临时文件与共享内存 | `/tmp` 达到 32 MiB 上限，`/dev/shm` 达到 16 MiB 上限；清理后均可继续写入。 |
| 文件数量 | 工作区通过空文件耗尽 8,192 个 inode 的额度并返回 `ENOSPC`；清理后恢复写入。 |
| 其他路径与挂载 | UID 1000 对镜像路径的写入失败。请求附加卷、隔离覆盖层和镜像声明卷均被拒绝。Docker 显示根文件系统只读，且没有 bind 或 volume 挂载。 |
| 内存和日志 | Docker 检查确认内存为 512 MiB、没有额外 swap，local 日志按 2 MiB 阈值保留两个轮转文件。未单独测量日志洪泛行为。 |
| 正常平台行为 | 热点收集、多轮聊天、试用、中控会话、S3/SSE、Pod 替换与队列恢复全部通过。 |
| 独立到期 | 终止生命周期服务后，脱离的任务继续运行，直到受保护 PID 1 到达截止时间并终止容器。随后重启生命周期服务并删除 Sandbox。 |

首次打包平台运行暴露了当前 DSH CLI 配置监视器所需 Node 启动参数缺失的问题。适配器传入 `--expose-internals`；通过的报告使用修正后的运行时镜像。Go Harness 测试包含面向本地模型服务的真实结构化历史序列化。

这些是临时可写内存限制，不是持久磁盘配额，也不是包含容器元数据的精确宿主机存储预算。tmpfs 消耗容器内存；内存密集任务可能先于文件额度耗尽而停止。Docker 配置与进程行为在本机实测；该实验不证明生产出口控制、身份体系、独立主机容量或恶意内核隔离。按[存储教程](../k8s/README.md#bounded-writable-storage)复现。
