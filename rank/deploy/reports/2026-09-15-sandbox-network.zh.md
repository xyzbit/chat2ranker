# Sandbox 网络限制验证 — 2026-09-15

[English](2026-09-15-sandbox-network.md) | 中文

专用 Docker 运行时通过了原生 TCP/UDP 出口检查，以及 minikube 上的七项完整平台检查。[机器可读证据](2026-09-15-sandbox-network.json)记录一致的运行时/服务端镜像、源码哈希、存储限制和独立到期结果。平台使用真实 DSH 进程与确定性本地模型，不调用外部模型。

| 检查 | 实测结果 |
| --- | --- |
| 可达对照 | 独立探测在受限运行时之外能够访问 TCP 和 UDP 监听服务。 |
| 目标限制 | UID 1000 可以访问允许的 IP 和 TCP 端口；另一个 IP、另一个 TCP 端口及 UDP 被阻止。目标端记录中没有被拒绝的探测。 |
| 受保护的启动 | 缺少策略或 NET_ADMIN 时，启动在命令守护进程运行前失败。初始化后的 PID 1、execd 和子进程均不具有 NET_ADMIN、NET_RAW；原生修改防火墙规则失败。 |
| 生命周期服务失联 | 强制终止服务后，允许的 TCP 仍可达，被禁止的 TCP/UDP 仍被阻止。实验重启服务并清理测试资源。 |
| IPv6 | 基础设施检查确认 IPv4、IPv6 默认拒绝规则已安装；没有测试外部 IPv6 流量。 |
| 策略冻结 | PostgreSQL 保留非空出口策略；策略不同的 Worker 不能领取任务。完整平台报告确认已接受的运行计划包含实验策略。 |
| 现有平台行为 | 热点收集、结构化多轮聊天、试用、中控对话、S3/SSE、Pod 替换和队列恢复通过。打包远程快照分别通过 SQLite 和双 Worker 的 PostgreSQL/River 路径。 |
| 存储与到期回归 | 相同镜像通过可写存储耗尽与恢复验证。生命周期服务失联后，受保护的 25 秒截止时间仍停止独立后台任务，此时供应商 TTL 为 90 秒。 |

平台实验为临时模型/工具 fixture 开放 `192.168.49.0/24` 的 TCP 8800。专用网络检查将策略收窄到一个目标地址与端口。空配置拒绝新的外部连接，DNS 不自动豁免。运行计划保留提交时的规则，因此运维更改 Worker 策略前必须排空或核对排队任务。

这些实测证明了本机的 IP/传输层限制，不证明生产目标授权、入站租户隔离、动态域名过滤、TLS 内容检查、独立主机容量或真实供应商 RPM/TPM 行为。存储仍是计入运行时内存的临时 tmpfs。复现步骤见[网络教程](../k8s/README.md#runtime-egress)；[实现决策](../../../.agents/notes/implemented/architecture/2026-09-15-sandbox-egress.md)说明规则的拥有关系与受保护的初始化过程。
