# 首次生产部署

[English](production.md) | 中文

本文定义最小可用生产拓扑，以及需要运维提供的部署决策。minikube 清单是可执行实验，不是可以直接公开到互联网的生产配置。物理多主机容量由运维后续验证。

## 部署与扩缩容

从一个 Rank API、一个中控服务、一个 Execution API 和有上限的 Worker 池开始。PostgreSQL 与对象存储持久化在可丢弃应用容器之外。Rank 当前派发采用单拥有者；增加并验证拥有者协调前，不横向扩展 Rank 副本。一个 Worker 管理若干配置的执行槽位，不为每个 Agent 或会话常驻一个实例。每次远程调用创建短生命周期 Sandbox；删除后数据库记录和 S3 产物仍保留。

KEDA 读取需要鉴权的 Execution 容量投影，根据在线、评测的可执行需求扩缩容，保留预热下限，并按模型与 Sandbox 容量约束副本上限。实验中每个 Worker 每类队列一个槽位，Worker 数量为 1～3。增加 Worker Pod 不会增加实验中固定 Docker Sandbox 主机的资源。生产必须测量实际运行时主机的容量，或采用接入调度器的 Sandbox Provider，才能声称运行时资源可以横向增长。

保持 API/Worker 限制与运行计划兼容。使用摘要固定运行时镜像，一并部署 API、Worker 协议和 Sandbox 镜像。升级 schema 前关闭自动扩缩容并排空生产者，使用迁移专属账号执行显式迁移，再恢复运行账号和流量。为 PostgreSQL、对象存储配置配套的备份、保留与恢复流程；未经恢复验证的备份不构成可用性保证。

## 访问与通信

通过 TLS 网关发布浏览器和公共 Responses API，并明确公开来源。保留 SSE，网关空闲及读取超时应大于配置的响应寿命。优先将浏览器的 API 和中控请求路由到同源地址。前端独立部署时，配置并验证准确的可信来源，不使用携带凭据的通配 CORS。

PostgreSQL、对象存储管理、Execution 管理、中控命令及 Sandbox 生命周期接口留在需要鉴权的私网。运行时额度申请使用专用路径、调用专属身份及有界请求。实验端口 30091 仅转发该路径；生产需保留在私网，跨主机使用 TLS。不要将实验 NodePort 或明文 HTTP 管理地址暴露到互联网。不向 Sandbox 进程注入 Execution 服务令牌、签名密钥或数据库凭据。

运维凭据、模型密钥和内部密钥存入部署环境的密钥管理系统。运维身份撤销可在不重启 Rank 的情况下重新加载。未实现双密钥过渡机制时，共享服务密钥和额度签名密钥应在协调排空后的维护窗口轮换。应用数据库账号仅有 DML 权限，迁移拥有者仅用于短生命周期部署任务。当前工作区面向可信的共享管理，不是完整的企业身份平台。

## 证据与保留

即使 tracing 不可用，已提交的会话与执行记录仍是权威状态。对象使用 Execution ID 与内容摘要组织；API 读取要求存在已提交的数据库引用。Worker 在上传成功后、引用提交前退出，可能产生孤立对象。运维配置的保留窗口应长于最长执行、恢复及清理间隔。Execution 终态且确认清理后，比较对应对象前缀与产物引用，再选择没有引用的对象删除。保留已引用证据以及活跃、尚未确认的尝试。暂未实现自动孤立对象回收。

分别观察接受、完成、失败、取消数量，排队耗时、首次输出时延、额度/资源阻塞及待清理积压。明确展示真实模型用量与缺失的价格信息。共享 TPM 采用估算并根据正数供应商用量调整，不是精确计费或严格费用上限。DSH 内部等待额度仍占用运行时。[验收报告](../reports/2026-09-15-management-access.md)记录具体实验依据；本地测量不能定义生产吞吐 SLO。

## 接入业务流量前

验证 TLS 与浏览器来源、凭据和轮换、持久卷恢复、Sandbox 隔离与出口规则、有界队列/执行/清理期限，以及模型账号额度的连接归属。在所选环境复跑[实验检查](README.zh.md)。使用有代表性的 Agent 工具和模型测量物理主机容量，再确定 Worker 上限与过载策略。现有实验不证明任意恶意代码隔离、平台高可用，或数据库及其所有备份同时丢失后的恢复能力。

网页登录要求前端、API 与中控路由位于同一公开来源。在 Rank 和 control-host 上配置精确的 HTTPS 来源，以校验变更请求来源并启用 Secure 会话 Cookie。当前进程内会话存储对应单 Rank 副本，维护重启后管理员需要重新登录。详见[管理访问](../../backend/README.md#management-access)。
