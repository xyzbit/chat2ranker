2026-09-13，以首次接入者身份使用平台创建真实模型 Agent、发布 `demo-integration` 端点、在接入侧栏创建限定范围的 Key，并运行[热点与聊天案例](../examples/responses-client/README.zh.md)。本记录区分已验证的能力与待完善的体验。

## 已处理的体验问题

| 问题 | 复现与影响 | 建议 |
| --- | --- | --- |
| 创建 Agent 后离开资产页 | 「新建 Agent → 创建并选择」跳到原有 Rank 对话，标题仍是原实验，需要再回资产列表找新 Agent。 | 资产页创建后打开新 Agent；从对话创建才保留对话上下文。 |

| 首次发布空表 | 无开发评测和历史版本仍展示四行空指标；回归集为空时按钮禁用。 | 优先展示版本、模型和回归选择，空状态明确说明阻塞原因。 |
| 无法按 Response ID 直达 | 接入代码已拿到 ID，但列表没有 ID 搜索，详情选择未保存到 URL，刷新丢失定位。 | 增加 ID 搜索和详情链接，让示例直接打开对应记录。 |

资产页创建后打开新 Agent，运行方式区分安装与连接选择，首次发布空状态说明缺失的评测证据和回归数据，调用记录支持按 ID 搜索及可刷新的详情地址。

## 文档与剩余缺口

旧命令行教程使用固定测试端点和 `@production`，与“端点名称即 model”的入门路径不一致。案例 README 和环境模板已改用端点名称，并解释 4173 前端代理与 8787 API 地址的关系。技术参考中的历史别名细节仍需与入门说明区分。

平台快速接入包含文件名、Node 版本、ESM 启动方式和成功输出。完整案例页提供可运行的热点与聊天应用、启动命令和验收方法。

流式片段要求完成确认并拒绝截断；完整案例覆盖取消与续聊状态，明确取消后新开会话的限制。「复制给 Agent」提供可直接读取的 Markdown API 参考。接入侧栏和文档提供独立 ZIP，包含中英文教程、依赖和预填端点的环境模板，无需克隆仓库，下载包中的密钥保持为空。

全新目录验收发现取消竞争：排队中的 Response 在取消期间进入运行状态时，API 会直接返回运行状态，未实际取消。取消逻辑会重试这个冲突并停止新获得的 Execution，已有终态保持不变。排查说明区分没有 Response ID 的请求拒绝，以及有调用记录的执行失败。

[调用反馈](response-feedback.md)支持排查与经过审核的数据集采集。多轮上下文、追加指令和工具结果仍需人工整理成独立文本，自动重放需要更丰富的用例格式。已验证的模型连接仍可能引用不可用模型，评测错误需要区分 Judge 故障与候选质量。

“允许外部工具”不等于“自动能检索今日热点”。本例由应用先获取实时数据，再单次调用 Rank。由 Agent 发起外部工具调用则需要应用执行函数并回传结果，通常不止一次 Responses 请求，场景教程应先明确采用哪一种方式。

## 内容验收

调用排查验收将聊天输入脱敏后保存，对冻结 Agent 和数据集 v1 运行评测，得到 1/1 个有效 Trial 通过。追加第二条经过审核的续聊用例后，数据集成为含两条用例的 v2，已完成 Run 仍保留 v1 和一条用例。这证明反馈流程可用，不代表 Agent 的整体质量；缺少定价信息时费用显示为不可用。

真实模型能保留两轮中的姓名、科技新闻偏好和 10 分钟时长。初次热点输出会从评论数推断“争议程度”，超出了标题资料能证明的事实；案例指令限制为标题翻译和概括，不做这类推断。来源与采集时间单独保留，便于核对。

本案例只验证 HN 社区最近 24 小时提交的标题，不代表国内热搜、多来源核查或全文研究。来源错误时停止并报错，不用模型记忆填补。真实调用结果、耗时和版本由 `npm run verify:demos` 写入本地验收产物，内容随新闻和模型变化。
